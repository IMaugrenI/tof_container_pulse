# Pulse Suite navigation plan

This document defines the first implementation step after the Pulse Suite roadmap.

The goal is to prepare navigation and shared page metadata without turning the current working Container Pulse runtime into a heavy multi-collector system too early.

## Current safe baseline

The current implemented page is:

```text
pulse.html -> Container Pulse
```

It is generated by:

```text
run.py -> pulse.generate_pulse(...)
```

This baseline must keep working while new pages are introduced.

## Page registry

`suite_pages.py` contains a small static registry for the six planned pages:

```text
Container Pulse -> pulse.html      -> active
Hardware Pulse  -> hardware.html   -> planned
Port Pulse      -> ports.html      -> planned
Storage Pulse   -> storage.html    -> planned
Service Pulse   -> services.html   -> planned
Security Pulse  -> security.html   -> planned
```

The registry intentionally has no side effects.
It does not:

- call Docker
- inspect host hardware
- scan ports
- read logs
- write output files
- import heavy collectors

This keeps imports cheap and makes it safe to use later from `run.py`, tests, templates, or documentation tooling.

## Navigation behavior

Future pages should share compact navigation pills:

```text
Container | Hardware | Ports | Storage | Services | Security
```

Rules:

- active implemented pages should link to their generated HTML files
- planned pages may be shown as disabled or marked `planned`
- planned pages must not pretend to be implemented
- language and theme controls stay separate from page navigation
- the current page should be visually marked as active

## Resource model

Navigation must never trigger data collection by itself.

Page generation should remain explicit:

```text
python3 run.py --once
python3 run.py --watch 60
```

Future collectors should be imported and executed only when their page is generated.

## Suggested next implementation steps

1. keep `pulse.html` generation unchanged
2. add navigation metadata from `suite_pages.py`
3. add a small rendered navigation row to `template.html`
4. keep planned pages non-clickable until their generators exist
5. add `Hardware Pulse` as the first real second page in a separate PR

## Do not do in this step

Do not add:

- hardware collection
- port inspection
- storage scanning
- service checks
- security checks
- automatic actions
- background daemons
- database storage
- external scans

This step is only for safe suite structure preparation.
